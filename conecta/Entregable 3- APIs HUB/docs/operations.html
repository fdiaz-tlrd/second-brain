Operations API — Panama Interoperability HUB (1.0.0-draft)

Download OpenAPI specification:

Panama Interoperability HUB — Developer Support: hub-support@[operator-domain]

Operational and availability services of the scheme: participant session (Sign On / Sign Off), echo test as an availability heartbeat, system notification messages (SNM) and scheduled windows, inbound participant→HUB operational events (inbound direction of the notification channel), and the operator-restricted endpoints to re-include or exclude a participant from the circuit. These services sustain the operational state of the scheme, not the monetary flow. The public status page is served without authentication, outside the transactional plane. Errors use application/problem+json with a reasonCode from the HUB error code catalogue.

Session

Participant Sign On / Sign Off

Sign On / Sign Off of the authenticated participant

Declares the participant's operational state to the scheme. Sign Off removes it from routing; Sign On restores it.

oauth2ClientCredentials

Inbound events

Participant→HUB operational events (inbound direction of the notification channel)

Submit a participant operational event to the HUB

Inbound direction of the notification channel: availability restored after an outage (the HUB reactivates routing without waiting for the next polling cycle), start/end of maintenance windows and any operational state change affecting routing. Idempotent by eventId.
