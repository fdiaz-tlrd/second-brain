Payments API — Panama Interoperability HUB (1.0.0-draft)

Download OpenAPI specification:

Panama Interoperability HUB — Developer Support: hub-support@[operator-domain]

Single transport channel for payment messages: the HUB validates structure, signature and credentials, records the operation for traceability and audit, and routes it to the destination participant (passthrough). This single channel carries the payment order (pacs.008), the reversal (pacs.007), the return (pacs.004) and the cancellation request (camt.056), all correlated to the original operation — there are no separate reversal or return endpoints. Status responses use pacs.002 semantics; the status-request message (pacs.028) maps to the status query endpoint. A malformed message is rejected technically with admi.002 semantics (HTTP 400).

Two representations are supported: application/xml carries the ISO 20022 message as-is (canonical passthrough), and application/json offers the simplified REST projection for a pacs.008 push order. For P2M payments originated by QR, the creditor may be given only as creditorId: the HUB completes the creditor party from the merchant directory. Errors use application/problem+json with a reasonCode from the HUB error code catalogue.

Orders

Payment message transport (pacs.008 / pacs.007 / pacs.004 / camt.056)

Submit a payment message

Submits a payment message to the HUB. With application/json, creates a push transfer (pacs.008 projection). With application/xml, transports the ISO 20022 message as-is: pacs.008 (order) and, correlated to the original operation, pacs.007 (reversal), pacs.004 (return) or camt.056 (cancellation request); the message type is declared inside the message itself and the HUB validates, records and routes it (passthrough). Send Idempotency-Key and retry with the same key on timeouts.
