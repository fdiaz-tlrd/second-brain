Subscriptions to the HUB's outbound notification channel: JWS-signed webhooks, at-least-once delivery with exponential retries and deduplication by eventId at the receiver.

Events are HUB notifications, not ISO 20022 messages. The JSON payload is not encrypted at message level, is signed with JWS and travels over TLS with mTLS. It contains no account or payment-message content and requires no business response; the receiver acknowledges it with HTTP 204. Payment events are how the HUB closes the timeout path: it notifies the origin (which reverses its debit internally) and the destination (which reverses the credit if it was applied) — retried until each side is available. Corrections beyond that are a regularisation (a new transaction with a new ID); there are no reversal invocations between participants through the HUB.

Event catalogue by category (see EventType):

  • PAYMENT — PAYMENT_TIMEOUT, PAYMENT_REVERSAL_REQUESTED, PAYMENT_STATUS_UPDATED
  • MERCHANT DIRECTORY — MERCHANT_UPDATED, MERCHANT_SUSPENDED, COLLECTION_METHOD_CHANGED (merchant events force invalidation of the affected P2M resolution cache)
  • OPERATIONAL — SYSTEM_NOTIFICATION, AVAILABILITY_CHANGED, MAINTENANCE_WINDOW
  • RECONCILIATION — RECONCILIATION_WINDOW_OPENED, RECONCILIATION_WINDOW_CLOSED, RECONCILIATION_FILE_AVAILABLE

Person-key lifecycle events are not emitted because key registration is local to each participant and the HUB keeps no central register of person aliases. Inbound participant→HUB operational events are posted on the Operations API (POST /events); the contract a participant must expose to receive these webhooks is the Participant Events API. Errors use application/problem+json with a reasonCode from the HUB error code catalogue.

Subscribe to HUB events

Authorizations:
oauth2ClientCredentials
header Parameters
Idempotency-Key
required
string <uuid>

Idempotency key (UUID) for safe retries (same key, same result).

Request Body schema: application/json
required
callbackUrl
required
string <uri> ^https://

HTTPS endpoint with a certificate trusted by the HUB. Registration validates syntax and scheme; availability is handled by the delivery retry policy.

eventTypes
required
Array of strings (EventType) non-empty unique
Items Enum: "PAYMENT_TIMEOUT" "PAYMENT_REVERSAL_REQUESTED" "PAYMENT_STATUS_UPDATED" "MERCHANT_UPDATED" "MERCHANT_SUSPENDED" "COLLECTION_METHOD_CHANGED" "SYSTEM_NOTIFICATION" "AVAILABILITY_CHANGED" "MAINTENANCE_WINDOW" "RECONCILIATION_WINDOW_OPENED" "RECONCILIATION_WINDOW_CLOSED" "RECONCILIATION_FILE_AVAILABLE"
