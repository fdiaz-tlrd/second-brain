Online resolution of person keys (aliases) and account-name verification.

Key registration, update and deregistration are handled by each participant, including identity checks, account binding and local fraud controls. The HUB does not store person aliases. It resolves a key by consulting the destination participant directory, and cross-network alias uniqueness is enforced by the batch consistency process. This API exposes resolution and account-name verification only.

A resolution may return up to 3 accounts for one key (multi-bank aliases — ACH Xpress). The initiating participant presents every returned account to the payer. The HUB performs the destination participant's confirmed-fraud check during resolution and returns the result as fraudIndicator.

Each resolved account carries only the data required to build the pacs.008 and drive the payer experience: holder name travels in clear over the mTLS channel; the national ID travels masked plus as an HMAC-SHA-256 hash (same programme key as the congruence process) so the initiating participant can match exactly without the ID ever leaving its processor in clear.

Errors use application/problem+json with a reasonCode from the HUB error code catalogue.

Resolution

Online key resolution (transactional path, federated across participant directories)

Resolve a person key

Resolves a key to the destination network and returns 1 to 3 accounts with the minimum data set to build the pacs.008 and let the payer choose the destination bank. Always online, never cached. The HUB consults the destination participant's directory (federated resolution) and enriches the answer with the confirmed-fraud indicator.

Verification

Account-name verification

Verify account-name

Confirms that the expected name matches the given account or key. Reused during merchant onboarding. The comparison runs on the normalised value (upper case, no accents); the result is expressed as full, partial or no match — the real name is never echoed back.
